# 当前 RAG 效果评测

评测日期：2026-10-16
评测范围：`rag/` 知识库引擎、公开 HTTP 接口、Widget 契约、检索闸门、引用回填、反馈闭环和安全边界。

## 结论

当前实现的工程契约表现稳定：自动化测试共通过 54 项，没有失败项。

| 检查 | 结果 | 说明 |
| --- | ---: | --- |
| 单元/集成测试 | 25 / 25 | 覆盖回答闸门、引用、摄取、增量同步、检索、安全和模型降级 |
| HTTP 验收 | 29 / 29 | 覆盖公开接口、跨域、会话、流式输出、反馈和安全隔离 |

这说明当前版本已经具备可交付的 RAG 基础能力，但还不能据此得出真实模型下的回答质量结论。单测和验收使用确定性的假 embedding 与假 LLM，真实模型质量、真实语料召回率、并发容量和线上成本仍需要单独测量。

## 已验证能力

### 回答正确性与证据约束

- 有明确证据时返回 `answerable`，并能把回答引用回具体文档、章节和行号。
- 跨文档问题可以分别挂载多条引用。
- 知识库没有覆盖时在检索阶段返回 `no_evidence`，不会调用 LLM 生成答案。
- 证据冲突时返回 `conflict`，并列展示冲突说法，不替用户选择其中一条。
- 只覆盖部分问题时返回 `partial`，显式列出缺失信息。
- 生成后校验发现矛盾陈述时会降级回答状态。
- 越界引用编号会被清理，不产生无法点击的引用。
- 未配置模型时仍能返回带引用的检索原文，并降级到关键词检索。

### 知识库与检索链路

- Markdown、TXT、PDF、DOCX、XLSX 五种格式均有解析覆盖。
- 不支持的文件会显式进入失败状态。
- 修改单个段落时只重算受影响的片段。
- 文件删除会在全量同步时清理对应文档。
- embedding 故障默认降级，并支持显式关闭降级。
- 模型切换后不会混用不同 embedding 模型的旧向量。
- 英文实体支持连写和带空格的检索形式。

### 公开服务与反馈闭环

- 外部站点可以通过公开 API 完成问答，CORS 和来源白名单生效。
- SSE 事件顺序稳定：`meta → delta* → citations → done → end`。
- 多轮会话由服务端维护，历史消息可恢复。
- 无法回答的问题会进入知识缺口 backlog。
- 用户负反馈会进入维护 backlog。
- 补录 Q&A 后可以重新验证同一问题并关闭对应缺口。

### 安全边界

- 会话不能跨知识库读取或追加。
- 会话不能跨站点复用。
- 非法 `topK`、空请求和非法 SSE 参数会在生成前返回 400。
- 上传要求有效 key 和合法来源。
- Widget 不引用 Agent Insight 的 Trace、Experiment、Skill 等宿主专有接口。

## 性能观察

验收中的确定性本地服务记录到检索阶段约 0–2 ms、整体服务阶段约 2–5 ms；快速模式可以把生成后校验从 3 次模型调用降到 2 次。这个数字不代表真实线上延迟，因为没有经过公网模型、真实 embedding 服务或并发压力。

真实评测需要补充：

1. 真实 embedding 与 LLM 的 p50/p95/p99 延迟。
2. 1、10、50、100 并发下的吞吐、错误率和 SQLite 锁等待。
3. 不同 `topK`、chunk 大小、重排策略下的 Recall@K 和成本。
4. 长文档、超长对话和大批量导入的内存峰值。

## 下一轮评测建议

建立一套独立的 golden set，至少包含 50–100 个问题，每条记录包括：

- 问题和问题类型
- 允许引用的文档/Chunk ID
- 标准答案或关键事实
- 是否应该拒答
- 允许的缺失项和冲突项
- 租户、来源和权限范围

按以下指标持续回归：

- 检索：Recall@K、MRR、nDCG、证据相关性。
- 生成：答案正确性、完整性、引用正确性、groundedness。
- 安全：跨租户访问、来源白名单、Prompt Injection、敏感信息泄露。
- 工程：p95 延迟、错误率、Token、单问成本、缓存命中率。

当前版本适合进入“真实模型 + 真实业务语料”的第二阶段评测；在这一步完成前，不建议对外宣称已经达到稳定的生产回答质量。

## Golden set 评测

已建立并运行 50 条 golden set：

- 数据集：[golden-set.json](../evaluation/golden-set.json)
- 运行脚本：`node --experimental-transform-types --import ./scripts/register.mjs scripts/evaluate-rag-effect.ts`
- 原始结果：[rag-effect-2026-10-16.json](../evaluation/rag-effect-2026-10-16.json)

第一轮 20 条通过 17 条，通过率 85%；修复中文疑问句覆盖率误判、关键词检索中的疑问套话、跨文档回答的确定性引用夹具后，扩展到 50 条时达到 50 / 50，通过率 100%。当前拒答准确率 100%，引用文档覆盖率 100%，确定性本地 fixture 的 p50/p95 延迟为 3/4 ms。

本轮修复包括：

1. 查询覆盖率计算会忽略“在哪里、是什么、多少、应该、存放”等疑问套话，保留真正的主题词，避免自然中文问法被误判为 `no_evidence`。
2. 补充查询覆盖率回归测试，锁定“日志存放在哪里”和“敏感信息应该存在哪里”两种表达。
3. Golden set 的确定性评测模型按最长问题优先匹配，避免短问题前缀覆盖复合冲突问题。
4. 关键词检索在构造 FTS 查询前去掉“位置、路径、期限、分别是什么”等疑问套话，同时保留原始问题给语义检索和回答闸门。

当前 50 条的 100% 只说明 fixture 语料和确定性评测链路通过；真实模型、真实业务语料和人工标注集仍需继续评估。
