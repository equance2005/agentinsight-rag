# 通用知识库助手：Phase 1 需求分析

## 1. 目标

为 Agent Insight 提供一套**通用、可复用**的知识库问答能力：既能在 Agent Insight 内部作为首个集成验证场景落地，也能脱离 Agent Insight 被任意网站复用。

功能边界以「通用知识库助手」为准，不绑定 Agent Insight 的页面结构、Trace / Run 数据结构或业务数据模型。交付物包含四部分：**知识库引擎**、**CLI 管理入口**、**网页管理台**、**可嵌入悬浮插件**。

## 2. 功能需求

| 编号 | 能力 | 验收口径 |
|-|-|-|
| FR-001 | 知识库创建（CLI） | CLI 支持从本地目录导入；支持 `--include` / `--exclude` 选择目录中的全部或部分文件；支持重复执行幂等 |
| FR-002 | 知识库创建（网页） | 网页支持上传本地文档并入库；支持选择「上传目录中的全部或部分文件」；大目录导入不阻塞 UI，可查看进度 |
| FR-003 | 多格式解析 | md、txt、Word(docx)、Excel(xlsx/xls)、PDF 至少五种格式可被正确解析为带定位信息的纯文本；无法解析的文件必须显式报错并记录原因，不得静默跳过 |
| FR-004 | 内容管理 | 知识内容支持新增、删除、修改、查询；查询结果可查看内容正文与其来源文档 |
| FR-005 | 来源可追溯 | 每个知识片段可反查来源文档、以及在文档中的位置（页码 / 工作表与单元格范围 / 标题路径 / 字符区间） |
| FR-006 | 增量同步 | 源文档变更后仅重建受影响部分，不触发全量重建；embedding 与分块结果可复用 |
| FR-007 | 问答对录入 | 支持直接录入问答对，作为独立知识记录类型参与检索，不经过文档解析链路 |
| FR-008 | 通用插件 | 以悬浮图标 + 对话框形式嵌入任意网页；集成方式为单段 `<script>` 标签 + `data-*` 配置；不假定宿主具备 Agent Insight API |
| FR-009 | 多轮与流式 | 插件支持多轮上下文问答，回答以流式方式增量呈现；流中断不影响已生成内容与已存记录 |
| FR-010 | 混合检索 | 关键词检索与语义检索可组合使用；语义检索不可用时自动降级为关键词检索，功能不中断 |
| FR-011 | 引用与定位 | 回答中的事实性陈述给出可点击引用；点击引用能定位到来源文档及其相关内容位置 |
| FR-012 | 拒答与不确定性 | 知识库未覆盖或检索证据不足时，明确说明无法可靠回答，并可提示用户补充信息；区分「部分可答」与「完全拒答」；不得以模型常识补齐成看似有根据的答案 |
| FR-013 | 反馈 | 支持对回答进行认可 / 不认可反馈；不认可可附带原因 |
| FR-014 | 维护者复查 | 无法回答的问题与低质量回答被记录，进入 backlog，供知识库维护者复查与补充 |
| FR-015 | 反馈闭环 | 维护者补充知识后，此前无法回答的同一问题转为可回答 |
| FR-016 | 通用性边界 | 知识库、检索、对话与插件配置与 Agent Insight 专有 Trace / Run / Execution / Experiment / Skill 数据结构解耦；`src/lib/kb/**` 不得 import 上述专有模型 |
| FR-017 | 双宿主一致性 | 同一份插件产物在 Agent Insight 之外的测试网页与 Agent Insight 页面分别集成，普通文档问答行为一致 |

## 3. 事实与约束

- 现有 Prisma datasource 为 **SQLite**（`prisma/schema.prisma`），生产部署另有一套 Postgres raw `pg` Pool 路径（`src/lib/storage/db-interface.ts`）。SQLite 无法加载 `sqlite-vec` 之类扩展，因此向量存储必须走 `VectorStore` 接口抽象，默认实现不依赖数据库扩展。
- 解析依赖已在 `package.json` 中：`mammoth`（docx）、`pdf-parse`（pdf）、`xlsx`（Excel）、`gray-matter`（Markdown front-matter）、`chokidar`（目录监听）。本需求**不新增**解析类依赖。
- 模型接入统一复用 `src/lib/storage/server-config.ts` 的 OpenAI 兼容配置（新增 embedding 配置项），与既有 LLM 调用方式保持一致。
- 插件产物为独立打包的单文件脚本，托管于 Agent Insight 的公开静态路径，**只依赖知识库 HTTP 契约**。
- 仓库已有 claim 级忠实度判定能力（`src/prompts/result-faithfulness-prompt.ts`，产出 `supported / contradicted / not_covered`）。该判定逻辑可被生成时校验复用，无需从零实现。
- 设计文档只描述设计意图，实现进度记录在 `docs/design/README.md` 清单。

## 4. 非目标

- 不做多租户 SaaS 计费、配额与组织隔离。
- 不做 GraphRAG / 知识图谱类结构化抽取。
- 不实现 OCR 与扫描件解析；扫描版 PDF 归为「解析失败并记录原因」。
- 不实现答案的跨语言自动翻译。
- 不在本阶段实现公开互联网检索兜底（联网核实属于 Agent Insight 既有能力，不与知识库拒答语义混用）。
- 不修改 Agent Insight 既有 Trace / 评估 / 实验链路的数据语义。

## 5. 风险

- **拒答被做假**：只调 prompt 写「不知道就说不知道」无法可靠拒答。必须实现检索闸门（无召回或最高分低于阈值即拒答且不调用 LLM）+ 证据闸门（claim 级归因判定）两道硬门控，并同时度量拒答率与误拒率，避免「一律拒答」通过验收。
- **引用不可定位**：若解析阶段丢失页码 / 单元格 / 偏移信息，后续无法补救。定位信息必须在解析环节一次产出并随 chunk 持久化。
- **增量同步退化为全量**：若 embedding 缓存键设计不当（如按文档而非按 chunk 哈希），改动一个段落后仍会重算整篇。缓存键必须为 `(model, dim, chunkHash)`。
- **插件样式污染宿主**：不隔离样式会与宿主 CSS 互相破坏。必须使用 Shadow DOM；对严格 CSP 站点保留 iframe 兜底。
- **通用性边界被侵蚀**：直接复用 Agent Insight 的 Trace / Execution 模型能让开发变快，但会使插件无法脱离宿主。以静态检查（`src/lib/kb/**` 禁止出现专有模型名）作为硬门禁。
- **PDF / Excel 解析质量参差**：复杂版式 PDF 与合并单元格 Excel 的文本顺序可能错乱。需在解析层记录质量告警，并在验收中覆盖含表格 PDF 与多 sheet Excel。
- **SQLite 向量规模上限**：暴力余弦在十万级 chunk 后延迟上升。以接口预留 pgvector / 外部向量库切换点，并在文档中标注规模阈值。

## 6. 验收范围

按六组验收场景组织，每组需可重复执行并产出结果记录：

| 组 | 场景 | 覆盖需求 |
|-|-|-|
| A 创建与格式 | CLI 导入本地目录；网页上传全部文件；网页选择部分文件；md/txt/docx/xlsx/pdf 五种格式各自导入并检查正文与定位信息 | FR-001~003 |
| B 管理与增量 | 知识内容增删改查；修改源文件后触发增量同步并断言重算片段数受限于受影响范围；录入问答对并确认可被检索命中 | FR-004~007 |
| C 插件集成 | 在 Agent Insight 之外的静态测试网页集成插件并完成普通文档问答；在 Agent Insight 页面集成同一产物并重复验证；断言插件网络请求不涉及专有接口 | FR-008、FR-016、FR-017 |
| D 多轮与交互 | 多轮追问保持上下文；流式增量输出；悬浮入口与对话框开合、移动端可用 | FR-009 |
| E 依据与拒答 | 四类问题分别验证：有明确答案、答案跨多个文档、知识库未覆盖、证据冲突；检查答案准确性、引用可定位性、拒答表现（部分可答与完全拒答均需覆盖） | FR-010~012 |
| F 反馈闭环 | 提交不认可反馈；确认低质量回答与无法回答的问题被记录并可在维护者视图复查；补充知识后同一问题转为可回答 | FR-013~015 |

关键量化断言：

- 可回答问题中，**无引用支撑的陈述句比例必须为 0**。
- 拒答率与**误拒率**同时测量并记录，两者不得只报其一。
- 增量同步后重算的 chunk 数必须显著小于全量重建的 chunk 数，并以计数而非耗时断言。
- 插件在两种宿主下的请求路径与响应行为差异为空集（除站点标识外）。
